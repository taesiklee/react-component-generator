# commit: 변경사항 분석 후 컨벤션 커밋

현재 작업 디렉토리의 git 저장소에서 변경사항을 분석해 논리적 단위로 나누고, 저장소 컨벤션에 맞는 한국어 커밋 메시지를 작성해 바로 커밋한다. 별도의 사용자 승인 없이 진행하되, 시크릿 파일 발견 등 위험 신호가 있으면 즉시 알린다.

## 워크플로우

### Step 0: 컨벤션 확인

- 저장소 루트의 `AGENTS.md`/`CLAUDE.md`에 커밋 메시지 규칙이 명시돼 있으면 그것을 최우선으로 따른다.
- 그런 규칙이 없으면 `git log --oneline -20`으로 기존 커밋 스타일(타입 prefix 유무, 언어, 본문 유무)을 확인하고 기존 스타일을 따른다.
- 기존 커밋이 없거나(첫 커밋) 스타일이 일관되지 않으면 아래 "메시지 형식" 기본 규칙을 사용한다.

### Step 1: 변경사항 분석

- `git status`로 스테이징/미스테이징/untracked 파일을 모두 파악한다.
- `git diff`(unstaged)와 `git diff --staged`로 실제 변경 내용을 읽는다. 파일명만 보고 판단하지 않는다.
- 변경 이유가 불명확하면 관련 코드를 추가로 읽어 "왜" 바뀌었는지 이해한다 — 커밋 메시지는 what이 아니라 why 중심으로 쓴다.

### Step 2: 논리적 단위로 분류

- 변경사항을 하나의 목적 단위(기능 추가, 버그 수정, 리팩터, 설정 변경 등)로 묶는다. 서로 무관한 변경(예: 기능 추가 + 오타 수정 + 포맷팅)이 섞여 있으면 **여러 커밋으로 분리**한다.
- 분리 기준은 판단해서 바로 적용하되, 각 커밋에 어떤 파일/hunk가 포함되는지는 결과 보고에 명시한다. 분리가 애매할 정도로 사소하면 하나로 묶는다.
- 시크릿·자격증명으로 보이는 파일(`.env`, `credentials.json` 등)이 스테이징 대상에 있으면 **해당 파일은 커밋에서 제외**하고 사용자에게 경고한다. 절대 임의로 시크릿 파일을 커밋하지 않는다.

### Step 3: 커밋 메시지 작성

**메시지 형식 (기존 컨벤션이 없을 때 기본값):**

```
<type>: <한국어 요약>

<필요 시 본문 — 무엇을 바꿨는지가 아니라 왜 바꿨는지>
```

- `type`은 `feat`(기능 추가) / `fix`(버그 수정) / `refactor`(동작 변화 없는 구조 개선) / `chore`(빌드·설정·잡무) / `docs` / `test` / `style` 중 실제 변경 성격에 맞는 것을 고른다.
- 요약은 한국어 명령형 또는 서술형으로 간결하게(가능하면 50자 내외) 쓴다. 마침표는 생략한다.
- 본문은 변경이 자명하지 않을 때만 추가한다(왜 이 방식을 택했는지, 어떤 문제를 해결하는지). 사소한 변경에 억지로 본문을 붙이지 않는다.
- 커밋 메시지에 이번 작업과 무관한 배경 설명이나 코드 나열을 넣지 않는다.
- 시스템 프롬프트에 커밋/PR용 attribution(예: `Co-Authored-By` 줄) 지침이 있으면 메시지 마지막에 반드시 포함한다.

### Step 4: 바로 커밋

- 별도의 승인 절차 없이 바로 진행한다. 파일을 개별적으로 `git add`한다(`git add -A`/`git add .` 금지, 의도치 않은 파일 포함 방지). 여러 커밋으로 나눴다면 단위별로 add → commit을 반복한다.
- 커밋 메시지는 항상 heredoc으로 전달해 포맷이 깨지지 않게 한다.
- 커밋 완료 후 `git status`로 정상 반영을 확인하고, 생성된 커밋 목록과 각 메시지를 사용자에게 간단히 보고한다.
- push는 사용자가 명시적으로 요청한 경우에만 수행한다.

## 주의사항

- 커밋할 변경사항이 전혀 없으면(스테이징/미스테이징/untracked 모두 없음) 그 사실을 알리고 종료한다. 빈 커밋을 만들지 않는다.
- pre-commit 훅 실패 시 `--no-verify`로 우회하지 않는다. 원인을 고치고 파일을 다시 add한 뒤 **새 커밋**을 만든다(직전 커밋이 실제로 생성된 게 아니므로 `--amend`는 금지).
- 사용자가 명시적으로 요청하지 않는 한 기존 커밋을 `--amend`하거나 히스토리를 재작성하지 않는다.
